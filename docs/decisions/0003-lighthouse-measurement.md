# 0003 Lighthouse: applied throttling locally, byte budgets as the guard

- Status: accepted
- Date: 2026-11-03

## Context

The 2.1 pages measured LCP 2,45–2,6 s against the 2,0 s mobile budget, with Lighthouse's default **simulated** throttling (Lantern) on `localhost`. The trace showed the page painting its LCP element (the H1) at 61 ms; the 2,6 s was Lantern's estimate.

Lantern rebuilds the load from the unthrottled trace and charges every request that finished before the LCP paint to the LCP. On `localhost`, everything finishes in under 50 ms, so the estimate included:

- ~145 KB (gzip) of Next.js and React runtime scripts. They are `async` and do not block rendering; on a real connection they arrive after the first paint.
- Both Onest files (63 KB). The headline has ă/â, so the Latin Extended file was always needed too.
- The render-blocking CSS file.

## Decision

1. **Real savings first** (all shipped):
   - One Onest file cut to Romanian + English, weight axis 400–700 (`npm run brand:font`): **29 KB instead of 63 KB**, one request instead of two, preloaded.
   - Metric-matched fallback faces (Arial / Liberation Sans, and Roboto for Android) generated by the same script, so a page that renders in the fallback looks like Onest.
   - `experimental.inlineCss`: Tailwind's CSS is inlined; no render-blocking stylesheet. FCP 1,2 → 0,8 s (simulated).
   - LeadForm, BaseMap and VideoEmbed in their own chunks (`patterns/Lazy.tsx`), loaded only on pages that render them; Analytics only when a GA4 ID is set.
   - `Photo` instead of `next/image`: importing anything from `next/image`, even `getImageProps`, adds its client component (about 5 KB) to every page.
2. **Local CI measures with applied throttling** (`throttlingMethod: "devtools"`): Chrome really slows the network and CPU, so script arrival order is real. Simulated throttling on `localhost` can never pass for an App Router site, because the runtime alone puts it over 2 s; that number does not describe what a phone sees.
3. **Byte budgets guard what Lantern was penalising**, so the switch cannot hide regressions: script ≤ 160 KB, fonts ≤ 32 KB, zero external stylesheets, TBT ≤ 200 ms, FCP ≤ 1,8 s, plus the LCP, CLS, accessibility (1,0) and best-practices (1,0) gates. SEO audits are asserted one by one; the SEO category score stays below 1,0 until Phase 8 only because of the deliberate `noindex`.
4. The **simulated** score is checked on the deployed Vercel preview (2.3 gate, PageSpeed Insights), where the network is real.

## Results (mobile, applied throttling)

- 2.2 start, scaffold pages (8 templates × 3 runs): performance 100, accessibility 100, best practices 100; LCP 1,3–1,4 s; TBT ≤ 20 ms; CLS 0–0,015. Simulated on `localhost`, for reference: LCP 2,3–2,5 s, FCP 0,8 s.
- 2.2 end, real pages (all 20 core URLs): performance 100, accessibility 100, best practices 100; LCP 1,3–1,4 s; TBT ≤ 10 ms; CLS 0.

## Consequences

- `font-display: optional` (revised in 2.2): with real page copy, `swap` made some text blocks rewrap when Onest arrived (the fallback matches Onest's width within 1% on average, but single lines vary by ±3%), and on `/despre` that pushed the page down by a line: CLS 0,2. With `optional` the preloaded font is used when it arrives with the first render; on a slow first visit that page stays in the metric-matched fallback and the next page uses the cached Onest. Text never jumps; CLS is 0 on every template.
- Any new client component or dependency has to fit the 160 KB script budget.
- `design-system/brand/fonts-src/Onest[wght].ttf` is the source of the served font; rerun `npm run brand:font` after updating it.

## Update: Lighthouse once per phase (2026-11-10)

- **Lighthouse no longer runs on every push.** At the owner's request it runs once, at the end of each phase, from `.github/workflows/lighthouse.yml` (started by hand) or locally with `npx @lhci/cli autorun`. The measurement rules above are unchanged.
- **Every push is guarded by `npm run check:budget`** (`scripts/checks/budget.ts`, in `ci.yml`). It loads every URL in `lighthouserc.json` in mobile Chromium and fails above 160 KB of script, 32 KB of fonts, or any external stylesheet. It catches the regressions that matter most between runs, but not LCP, CLS or TBT; those wait for the phase-end run.
- A new page joins both checks by adding its URL to `lighthouserc.json`.
